# Post-mortem: the 2026-08-17/18 gaia queue run

**Status:** committed via PR #211 for human review; the recovered work ships as PRs #212-#216.
**Author:** reconstructed by Claude (Opus 5) on 2026-08-18, from git objects, `.gaia-runs/` logs and `~/.claude/projects/` session transcripts.
**Scope:** what ran, what it produced, what was lost, and what should be published.

---

## Executive summary

Three of the assumptions this investigation started from turned out to be wrong, and correcting them changes the conclusion entirely.

1. **The run was not a runaway agent.** It was `scripts/gaia_run_queue.sh`, launched by hand as `sh scripts/gaia_run_queue.sh`, doing exactly what it is written to do: enumerate the whole open backlog, group it into milestone batches, and invoke one `claude -p` per issue. The agents were correctly scoped and obedient — every one of the 19 sessions received *"for THIS issue only"* and *"Do not commit"*, and **not one agent ever committed, pushed, opened a PR, or deleted a branch.** The looping, committing, branching and deleting were all the shell script.

2. **The run was never stopped.** The kill at ~05:50 on 2026-08-18 terminated one `claude -p` child. The parent loop survived and immediately started issue #166. It was still running, and still writing to the working tree, **12h15m after launch**, when this post-mortem began. It was stopped at 06:47 on 2026-08-18.

3. **The work *was* pushed — and then deleted by the pipeline itself.** Every batch reached `git push -u origin` and succeeded. The next line, `gh pr create --draft … --json number`, failed with `unknown flag: --json` — `gh pr create` has no such flag (the installed `gh` is 2.96.0, current; this is a script bug, not a stale toolchain). That failure invoked the abandon path, which ran `git reset --hard`, `git clean -fd`, `git branch -D` **and `git push origin --delete`**, erasing the branch from the remote. One wrong flag cost nine pushed branches and roughly eleven hours of work.

Nine commits were recovered and are permanently tagged. One further body of work — issue #176, 730 insertions — was destroyed by `git reset --hard` and is **not** in the object database, but is reconstructable from its surviving transcript.

### 4.6 Guardrails — now implemented in `scripts/gaia_run_queue.sh`

Items 1–4, 6 and 7 are **implemented** (uncommitted, alongside this document). Items 5 and 8 remain open.

1. ✅ **A stop condition.** `GAIA_MAX_BATCHES=N` stops after N batches; `0` (the default) drains the queue as before. Checked at the top of the batch loop, so remaining batches are left untouched.

### 4.7 Conflict arbitration and the auditor merge gate

Two mechanisms were added to address the failure mode that produced the #163/#154 collision, and the weaker one that let an unreviewed change reach a merge.

**Arbitration (`find_conflicting_prs` → `arbitrate_pair` → `arbitrate_against_rivals`).** Because batches are cut from `main` in parallel, two agents can propose competing designs for the same module without either seeing the other. After a PR is marked ready, its branch is tested against **every other open `gaia/*` PR**: changed-file overlap is the cheap prefilter, and `git merge-tree` is the real test — it detects genuine conflicts rather than mere co-location, and moves no ref, index, or working tree (`--write-tree` does add unreachable tree objects, which a normal gc collects). On a hit, an **independent `gaia-auditor`** receives both diffs and both issue statements, is *not* told which branch is "ours", and returns a structured verdict:

```json
{"verdict": "A" | "B" | "reconcile" | "escalate",
 "confidence": "high" | "medium" | "low",
 "rationale": "...", "reconciliation": "..."}
```

The verdict is posted to **both** PRs so the losing side is never silently dropped. A PR that loses, or any `reconcile`/`escalate` outcome, is returned to draft via `gh pr ready --undo` and never auto-merges. Verified against the real case: the #163/#154 pair is correctly detected as conflicting on `src/models/observability.py`, and the non-conflicting #39/#158 pair is correctly skipped by the prefilter.

**Auditor merge gate (`audit_pr_convergence`).** Copilot going quiet was previously the whole convergence signal, but an unchanged comment fingerprint reads identically whether the revision pass *addressed* the feedback or *ignored* it. A merge now requires both: Copilot quiet **and** an independent auditor satisfied. The auditor reads the final diff against the outstanding review comments and must confirm that each substantive comment is addressed or correctly rebutted, that the change resolves the issues it claims to close, and that it introduces no new problems. It returns:

```json
{"converged": true | false, "blocking": ["..."], "rationale": "..."}
```

It **fails closed** — unparseable output means *blocked*, not merged — and posts its verdict on the PR either way. Both agent invocations are toggleable (`GAIA_ARBITRATION`, `GAIA_AUDIT_GATE`), both default on.

Caveats worth knowing: `gh pr ready --undo` is documented as *"if supported by your plan"*, so verify it against this org once; and both mechanisms cost an extra `claude -p` invocation per PR (arbitration only when a conflict is actually detected).
