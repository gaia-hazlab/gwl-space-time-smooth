### Physics assessment

FAO-56 Penman-Monteith reference ET is the right formula, but the plan to source it does not work.
- FuXi (the preferred model) and GraphCast output t2m, u10/v10, msl and tp. They output no surface shortwave or longwave radiation, and FuXi gives humidity only on pressure levels.
- So 'use AI-model radiation/humidity/wind' is not possible for the forecast path. Rn would come from ERA5-Land (ssrd/strd, d2m), which works for hindcasts only, or from a radiation diagnostic.
- Reference ET0 is for a short-grass reference. Forested Cascade cells need a crop or canopy coefficient and a separate interception term, otherwise the result is no more physical than Hargreaves-Samani.
- Switching PET formula invalidates the existing bucket calibration and creates a step change at the hindcast-to-forecast transition (lead 0).
- TerraClimate PET is already Penman-Monteith-type.

Land-surface-modeling review confirms full **FAO-56 Penman-Monteith reference ET** is the preferred
formulation — this is also what the group's own agroseismology paper uses
([Shi et al. 2026, *Science* 392(6795):306-310](https://doi.org/10.1126/science.aec0970), Eq. S9),
not a temperature-only proxy.

PET in this repo currently has two paths, neither of which is full Penman-Monteith:

- **TerraClimate path** (`fetch_terraclimate.py`) — takes TerraClimate's own `pet` product, which
  TerraClimate computes internally via a Penman-Monteith-type reference ET (Abatzoglou et al. 2018).
  Fine as an external product, but we don't control or verify its inputs.
- **PRISM path** (`fetch_prism_monthly.py` / `fetch_prism_daily.py`) — as of the Hargreaves-Samani
  fix (superseding the earlier Hamon implementation), computes ET from Tmax/Tmin/Tmean + latitude
  only. Hargreaves-Samani is FAO-56's own recommended substitute *when radiation, wind, and humidity
  are not measured* (Allen et al. 1998, Ch. 3) — a real improvement over Hamon, but still not full
  Penman-Monteith, because PRISM does not carry net radiation, soil heat flux, wind speed, or vapor
  pressure deficit.

## What's needed to swap in real Penman-Monteith

FAO-56 Eq. 6: `ET0 = [0.408*Δ*(Rn-G) + γ*(900/(T+273))*u2*(es-ea)] / [Δ + γ*(1+0.34*u2)]`
(daily form; see Shi et al. 2026 Eq. S9 for the sub-daily variant). Needs, gridded over the domain:

- [ ] **Net radiation** (Rn) — shortwave + longwave, or a proxy (cloud cover + solar angle) if direct
      radiation isn't available.
- [ ] **Wind speed** (u2, 2 m) — currently not ingested from any source.
- [ ] **Humidity / vapor pressure deficit** (es, ea) — currently not ingested from any source.
- [ ] **Soil heat flux** (G) — usually approximated as ~0 at daily timestep (FAO-56 convention);
      likely not a new data-ingestion item, just a modeling choice to make explicit.

Candidate sources for the three real gaps (radiation, wind, humidity), in rough order of fit:

1. **AI weather models via [earth2studio](https://github.com/NVIDIA/earth2studio)** (GraphCast/ACE2/
   StormCast) — already the target forcing interface for the forward-forecast path (#71), and these
   models output radiation/humidity/wind alongside precipitation, so this is the natural place to
   pick them up rather than a separate ingestion path.
2. **ERA5-Land reanalysis** — already used as an independent cross-check (#72); could double as a
   real-input source for hindcast-mode Penman-Monteith if AI-model fields aren't wanted for the
   observed/hindcast path.
3. A dedicated **met-station network** (e.g. AgWeatherNet, RAWS) if point-anchored radiation/wind/
   humidity is preferred over gridded reanalysis for the observed path — unexplored, flagging as an
   option rather than a plan.

## Scope / sequencing

This is a **later-stage enhancement**, not a blocker: Hargreaves-Samani is an honest, FAO-56-endorsed
stand-in for now. This naturally follows the forward-forcing work in #71 (which already needs an
earth2studio ingestion path for AI-model fields) — do the radiation/wind/humidity ingestion as an
extension of that same pipeline rather than a separate one, then swap PRISM's/the daily budget's PET
call from `hargreaves_samani_pet_mm`/`hargreaves_samani_pet_per_day_mm` to a new
`penman_monteith_pet_mm`, keeping Hargreaves-Samani as the fallback when the new inputs aren't
available for a given window (e.g. hindcast periods before an AI-model archive starts).

Relates: #71 (forward AI forcing), #72 (ERA5-Land cross-check), #39 (Earth2Studio scope). See
`docs/peer_review.md` §3.6 for the original review that flagged this.
