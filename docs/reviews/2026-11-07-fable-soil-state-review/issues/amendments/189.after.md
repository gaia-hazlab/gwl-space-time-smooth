**In plain words:** Start with one documented error value per sensor type and a frozen list of held-back sensors; then the operators.

**Audit verdict:** split

> **Agents:** implement one slice per PR, use `Refs #189` (never `Closes`), and leave this issue open until every slice is accepted.

### Specification

Split into three. (a) Agent-ready now: source one documented σ per non-dv/v sensor (instrument spec or validation paper, with citation), retire the two inconsistent placeholder sets (observability.py STREAMS; make_twin_gif.py:80-83), and pre-register station/time/domain holdouts as a versioned file. (b) Record schema plus point/probe-depth/satellite operators, after the #187 draft. (c) A gauge flux operator through the water-budget model's baseflow plus routing, and an aquifer-head operator. Acceptance should add: a gauge datum is never mapped linearly onto head; the probe-depth operator is tested against a known profile.

### Problems found

- Very broad: schema, eight operators, block R, holdouts, latency and provenance in one issue.
- Blocked by #187, which is stuck behind epic #171, although the per-sensor σ sourcing and the holdout pre-registration need no contract.
- The gauge operator as written is physically wrong.
- Holdouts must be frozen before the #192 tuning; this issue is where that happens, but the ordering is not stated.

### Physics assessment

A single time-aware observation record with datum age, native support, QC, R-block ID and a permanent role is the right missing layer. Part of it has landed: the measurement_target classifier, the water_table_observations() screen, and water_table_point_footprint, which refuses non-water-table wells (observability.py:945-978). Physics problems. 'Basin-integral gauge operators' as a linear average of head is wrong: discharge is a flux, related nonlinearly to storage and gradient. Yet STREAMS models USGS gauges as informing 'gwl' with kind='flux' and a flat noise of 0.05 (observability.py:899). The operator must be the model's own baseflow/runoff prediction, h(x) from the water-budget model, ideally routed (September audit S4). Soil probes at 5/20/50 cm need a depth operator onto the root-zone storage, not the identity. The aquifer-head operator for deep or confined wells remains open (2026-08-20 comment). The added task on per-sensor σ is correct: SMAP's ubRMSE target of 0.04 m³/m³ is unused, and the NWIS/SNOTEL placeholders are not traceable to instrument specs.

### Order and dependencies

Blocked by: #187, #9.

## Why this is needed

The repository already fetches and/or models NWIS wells, SNOTEL/SCAN/USCRN soil moisture, SWE, USGS discharge, SMAP, and seismic dv/v; it also has point, satellite, channel, basin, and coda-footprint concepts. These are not yet exposed through one time-aware operational record consumed by a cycling filter.

The missing layer is not another downloader. It is a consistent observation object with actual datum age, native spatial/depth support, QC/bias state, covariance metadata, and a permanent assimilation-versus-validation designation.

## Dependencies

- Depends on #187 for the observation schema.
- Feeds #188's cycling nowcast.
- Builds on #28 (SNOTEL), #29 (native-scale satellite comparison), #30 (real dv/v), #6 (continuous-well validation), #9/#46 (aquifer screening), and existing USGS gauge/soil-station fetchers.
- Must implement #167 (datum age is not revisit cadence).
- Must respect #164/#165/#168 for correlated dv/v error, petrophysical gain, and coda-operator uncertainty.
- Coordinate with #156 for fixture-backed parser/assimilation tests.

## Tasks

- [ ] Define one observation-record table/dataset: value, units, time, arrival time, datum age, coordinates, depth/support, stream, QC, bias flag, operator ID, R block ID, and role.
- [ ] Adapt existing NWIS, AWDB/SNOTEL/SCAN, USCRN, gauge, SMAP, and seismic outputs without duplicating their fetch logic.
- [ ] Implement screened-well operators and soil-probe depth operators.
- [ ] Implement basin-integral gauge operators and retain satellite/coda native footprints.
- [ ] Construct block/non-diagonal R where observations share references, stations, retrieval errors, or processing choices.
- [ ] Assign stations/times to assimilation, calibration, or fully withheld validation before cycling.
- [ ] Handle late, missing, stale, and asynchronous observations explicitly.
- [ ] Persist operator and QC provenance with each analysis.

## Acceptance criteria

- A mixed fixture containing a well, soil probe, gauge, satellite pixel, and dv/v datum can be evaluated in one observation-space call.
- Actual timestamp/age, not nominal revisit interval, controls lag handling.
- Assimilation and validation records are mutually exclusive.
- Every residual is computed at the observation's native spatial and depth support.
- Correlated observations are not treated as independent diagonal-R replicates.
- Existing fetchers and deterministic native-scale validation remain usable.

None of today's values traces to an instrument spec.
