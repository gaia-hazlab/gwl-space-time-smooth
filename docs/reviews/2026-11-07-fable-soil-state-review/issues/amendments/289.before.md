Part of the MODFLOW 6 groundwater core. Plan and design record: `docs/reviews/2026-10-18-modflow-groundwater-core/plan.md` (#273); decision issue #265. Epic: #274.

## Purpose
The cycling filter (#188) must advance N MODFLOW members, stop them between stress periods,
read and write heads, and resume, with each member's parameters and forcing held separately.

## Deliverable
`src/models/mf6_ensemble.py`: `Ensemble(members, param_sets, forcing_perturbations, seed)` that
advances all members one stress period through modflowapi, exposes `get_heads()` and
`set_heads(increment)` per member, keeps member identity (#187), and books every head increment as
dV = V(h_a) - V(h_f), where V is MF6's own piecewise storage function summed over layers (S_y over
the unsaturated part of each convertible cell, S_s times saturated thickness), in a DA-increment
ledger separate from the physical budget. An analysis table above the MF6 top is moved into
LSM root-zone storage and booked on both stores; every clip (dry cell, negative SWE, root zone
outside [theta_wp, theta_sat] x d_root) is its own booked increment. Uses the #280 driver
for the land-surface half.

modflowapi exposes heads as a read-only copy (`apimodel.X`); writing goes through the xmipy
`get_value_ptr` / `set_value` calls on the head address, and must be done between time steps
(modflowapi `timestep_end` callback). Cite Hughes et al. 2022 (doi:10.1016/j.envsoft.2021.105257).

## Inputs and conventions
Seeds through the single RNG helper (#155). Runs on the #275 fixture in CI.

## Acceptance
- With no update, an N-member run equals N independent runs bit for bit.
- Single-column fixture: impose increments that cross a layer bottom and the model top, then run
  one zero-flux stress period; MF6's storage budget term equals the booked dV to solver closure.
- Members stay independent: perturbing one member's parameters changes only that member.

## Hard blockers
Blocked by: #275, #280, #155.
